What is using port 3000 on my Mac? Find and stop it

When a dev server fails with "address already in use" or "EADDRINUSE", something on your Mac is already listening on that port. Terminal can tell you what, and then you can decide whether to stop it.

1. Find the process

Replace 3000 with your port number:

lsof -nP -iTCP:3000 -sTCP:LISTEN

The flags: -n and -P skip host and port name lookups, -iTCP:3000 selects TCP port 3000, and -sTCP:LISTEN keeps only sockets that are listening (not clients connected to it). The output looks like this:

COMMAND   PID  USER   FD   TYPE  DEVICE SIZE/OFF NODE NAME
node    48213  andy   23u  IPv6  0x...   0t0  TCP *:3000 (LISTEN)

The COMMAND and PID columns tell you what holds the port. If nothing is printed, no process owned by your user is listening there. Try again with sudo to see processes owned by other users.

To see the full command line of the process, which helps you recognise it:

ps -p 48213 -o pid,ppid,command

2. Stop it

If it is a leftover dev server that you recognise, ask it to quit:

kill 48213

kill sends SIGTERM, which lets the program shut down cleanly: close files, finish writes and release the port. Wait a moment and run the lsof command again to confirm the port is free.

If the process ignores SIGTERM and is still there, force it:

kill -9 48213

kill -9 sends SIGKILL, which ends the process immediately and gives it no chance to clean up. Use it as a last resort. It can leave lock files or half-written data behind. Never kill a process you cannot identify, and be especially careful with system processes and anything owned by root.

Some tools respawn what you kill. If the port is taken again straight away, the parent is restarting it (a file watcher, a process manager, or an IDE run configuration). Look at the PPID in the ps output and stop the parent instead.

3. Ports 5000 and 7000: AirPlay Receiver

On recent versions of macOS, the AirPlay Receiver feature listens on ports 5000 and 7000. If your app or a framework such as Flask defaults to port 5000, it may fail to start because of this, and the process shown by lsof will be a system one (often named ControlCe, short for Control Center).

You have two options. The simpler one is to run your server on another port. Otherwise, open System Settings → General → AirDrop & Handoff and turn off AirPlay Receiver. Doing so disables receiving AirPlay streams on that Mac, so only do it if you do not use that feature.

4. Ports published by Docker

If a container publishes the port, lsof shows a Docker process (for example com.docker.backend) rather than your app. Killing that process would disrupt Docker itself. Find the container instead:

docker ps --format 'table {{.Names}}\t{{.Ports}}'

Then stop the one that publishes your port:

docker stop <container name>

If you started it with Docker Compose, docker compose down in that project folder stops its containers cleanly.

5. Check everything that is listening

To list all TCP listeners at once:

lsof -nP -iTCP -sTCP:LISTEN

This is a good way to spot forgotten servers (old databases, test servers, tunnels) that keep running in the background.

If nothing seems to be listening

  • Run the command with sudo; the holder may belong to another user.
  • Check whether your server binds IPv6 or a specific address; the NAME column shows it.
  • Wait a few seconds. A port closed by a crashed process can stay in a TIME_WAIT state briefly, and the next start usually succeeds.
