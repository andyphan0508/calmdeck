Free up disk space on a developer Mac: node_modules, Docker, caches

Developer tools quietly collect tens of gigabytes: dependency folders, container images, package caches. Most of it can be regenerated, but a few commands, run carelessly, delete data you want. Measure first, then clean the big items one at a time.

1. Measure first

List the largest folders in your home directory and in Library:

du -hd 1 ~ 2>/dev/null | sort -h | tail -15
du -hd 1 ~/Library 2>/dev/null | sort -h | tail -15

Check the usual suspects directly:

du -sh ~/.npm ~/.gradle ~/Library/Caches/CocoaPods ~/Library/Caches/Homebrew 2>/dev/null
docker system df

2. node_modules

Every JavaScript project keeps its own copy of its dependencies. They can be reinstalled with npm install (or pnpm, yarn), so deleting them in projects you are not working on is safe. First list them with sizes. The -prune option stops find from descending into each one, which keeps the search fast and avoids nested duplicates:

find ~/code -name node_modules -type d -prune -exec du -sh {} + 2>/dev/null | sort -h

Replace ~/code with the folder where your projects live. After reviewing the list, delete the ones you do not need:

rm -rf ~/code/old-project/node_modules

Delete them one project at a time, picking from the list. Run npm install again when you come back to a project.

3. Docker

See what Docker uses:

docker system df

Then remove unused data in increasing order of risk:

docker builder prune

This clears the build cache only. Containers, images and volumes are not touched. Next:

docker system prune

This removes stopped containers, unused networks, dangling images and unused build cache. It asks for confirmation. It does not remove volumes, and it keeps images that a container uses. To also remove every image not used by a container:

docker system prune -a

You will need to pull or rebuild those images again later.

Volumes need extra care. Volumes often hold database data. docker system prune --volumes and docker volume prune delete unused volumes permanently, and "unused" means no container currently references it, which includes a database container that is merely stopped. List them first with docker volume ls, and only remove ones you are certain are disposable.

After a large cleanup, Docker Desktop's disk image may not shrink right away, so the free space shown in macOS can lag behind what Docker reports.

4. Homebrew

brew cleanup
brew autoremove

brew cleanup deletes old versions of installed formulae and cached downloads. brew autoremove removes dependencies that nothing needs any more. Both are safe, though a formula you installed only as a dependency of something you removed will go too. Run brew autoremove --dry-run first if you want to see the list.

5. Package manager caches

These caches only speed up future installs. Clearing them is safe; the cost is re-downloading packages later.

  • npm: npm cache clean --force (the cache is in ~/.npm).
  • pnpm: pnpm store prune removes packages no project uses. It leaves the packages that are still referenced.
  • Yarn: yarn cache clean.
  • pip: pip cache purge; pip cache dir shows where it is.
  • CocoaPods: pod cache clean --all (cache in ~/Library/Caches/CocoaPods).
  • Gradle: stop the daemons with ./gradlew --stop and then remove ~/.gradle/caches. The next build downloads dependencies again, so do it while you have a network connection.

6. Xcode

If you build for Apple platforms, Xcode's DerivedData, simulators and device support are usually the largest single item. See our guide to clearing Xcode DerivedData, Archives and simulators.

Habits that help

  • Check docker system df now and then instead of waiting for a full disk.
  • Delete node_modules from finished projects; it costs one command to restore.
  • Never delete something you cannot name. Cache folders are safe because you know what they are.
