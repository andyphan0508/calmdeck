How to safely clear Xcode DerivedData, Archives and simulators on Mac

Xcode is one of the largest disk users on a developer Mac. Most of that space is regenerable build output and simulator data, but a few folders hold things you cannot rebuild. This guide shows how to measure first, what is safe to remove, and what to keep.

Quit Xcode and any running simulators before deleting anything below.

1. Measure first

See where the space is going before you delete anything:

du -sh ~/Library/Developer/Xcode/DerivedData
du -sh ~/Library/Developer/Xcode/Archives
du -sh ~/Library/Developer/Xcode/iOS\ DeviceSupport
du -sh ~/Library/Developer/CoreSimulator

A missing folder just means you have never used that feature. Sizes of 10 to 50 GB for DerivedData and CoreSimulator are common on a Mac that has built many projects.

2. DerivedData: safe to delete

DerivedData holds build products, indexes and intermediate files. Xcode recreates it on the next build, so deleting it loses nothing except time: the first build and the first indexing pass afterwards will be slower.

rm -rf ~/Library/Developer/Xcode/DerivedData/*

To clear a single project, delete only its folder inside DerivedData (the folder name starts with the project name followed by a hash). Clearing DerivedData is also the standard first fix for odd build errors and stale indexing.

3. Archives: be careful

Archives are the builds you created with Product > Archive. They live in ~/Library/Developer/Xcode/Archives, grouped by date. Unlike DerivedData, they cannot be regenerated exactly: each archive contains the dSYM files for that build, and you need the matching dSYMs to symbolicate crash reports from that version.

  • Keep the archive (or at least its dSYMs) for every version you shipped to users and still support.
  • Archives of builds you only tested, or of versions long since replaced, are safe to delete.
  • If you upload dSYMs to a crash reporting service or to App Store Connect, you have a second copy, but verify that before deleting the local one.

4. iOS DeviceSupport

When you connect a physical device, Xcode copies that device's system symbols into ~/Library/Developer/Xcode/iOS DeviceSupport, one folder per OS version, often several GB each. Old folders for OS versions you no longer test on can be deleted. Xcode recreates a folder the next time you connect a device running that version, which takes a few minutes. The same applies to watchOS DeviceSupport and tvOS DeviceSupport.

ls ~/Library/Developer/Xcode/iOS\ DeviceSupport
rm -rf ~/Library/Developer/Xcode/iOS\ DeviceSupport/"<folder name>"

5. Simulators

Simulator data lives in ~/Library/Developer/CoreSimulator. Do not delete that folder by hand; use simctl, which keeps Xcode's records consistent.

First remove simulators that no longer work with your installed Xcode, usually left over from older versions:

xcrun simctl delete unavailable

This is safe: it only removes simulators that Xcode already cannot use. Then look at the downloaded simulator runtimes, which are often the biggest item:

xcrun simctl runtime list

The output lists each runtime with an identifier and its size. Delete the ones you no longer need by identifier:

xcrun simctl runtime delete <identifier>

You can also manage runtimes in Xcode under Settings > Components. A deleted runtime can be downloaded again, but the download is large, so keep the runtimes for the OS versions you actually target.

Deleting a simulator device erases the apps and data installed on it. If you rely on test data stored in a particular simulator, keep that one.

What not to delete

  • ~/Library/Developer/Xcode/UserData: your key bindings, code snippets and font and color themes.
  • Archives for shipped versions, as described above.
  • Provisioning profiles in ~/Library/MobileDevice/Provisioning Profiles unless you know they are unused.
  • The Xcode app itself, unless you have decided to remove an old copy of Xcode.

A short routine

  1. Quit Xcode and the Simulator.
  2. Measure with du -sh.
  3. Clear DerivedData.
  4. Run xcrun simctl delete unavailable and remove runtimes you do not use.
  5. Remove DeviceSupport folders for old OS versions.
  6. Review Archives by hand.
